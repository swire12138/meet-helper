# 抽象专家知识画像实施任务清单

## 使用方式

本清单按“从底层存储到上层问答”的顺序安排，尽量减少返工。

每个任务包含：

- 目标
- 主要产出
- 依赖
- 验收点

## Phase 0：冻结当前旧逻辑边界

### T0.1 盘点现有画像写入路径

- 目标：明确当前哪些地方会直接修改画像、会话和会议分析结果。
- 主要产出：
  - 现有入口清单
  - 现有数据文件清单
  - 可复用模块清单
- 依赖：无
- 验收点：
  - 能明确列出 `profileBuilder`、`chatStore`、会议分析链路的现状写入点

### T0.2 定义兼容策略

- 目标：决定新专家系统上线前，旧画像系统是否保留只读兼容。
- 主要产出：
  - 兼容说明
  - 迁移开关策略
- 依赖：T0.1
- 验收点：
  - 明确“旧数据继续读 / 停止新增 / 平滑迁移”的策略

## Phase 1：专家中心化数据结构

### T1.1 定义专家目录结构

- 目标：落地 `experts/{expertSlug}` 文件结构。
- 主要产出：
  - 目录创建函数
  - 路径工具函数
  - 专家存储约定
- 依赖：T0.2
- 验收点：
  - 能创建专家目录及子目录：
    - `portrait`
    - `meetings`
    - `memory_units`
    - `events`
    - `aggregates`

### T1.2 定义 `expert.json` schema

- 目标：定义抽象专家画像的主实体。
- 主要产出：
  - `expert.json` schema
  - 校验函数
- 依赖：T1.1
- 验收点：
  - 至少包含：
    - `slug`
    - `name`
    - `domain`
    - `description`
    - `status`
    - `createdAt`
    - `updatedAt`

### T1.3 定义会议归档 schema

- 目标：统一单次会议归档结构。
- 主要产出：
  - `meta.json` schema
  - `summary.json` schema
  - `images.json` schema
- 依赖：T1.1
- 验收点：
  - 每场会议能独立存储全文、摘要、专家归属、时间信息

## Phase 2：会议入库与专家归属

### T2.1 录屏开始前绑定专家

- 目标：每次会议开始前必须手动选择抽象专家画像。
- 主要产出：
  - UI 选择器
  - 会话状态绑定
- 依赖：T1.2
- 验收点：
  - 未选专家时不能进入专家知识更新链路

### T2.2 会议结束后归档全文与元数据

- 目标：每次会议都独立归档，不再只保留累积后的画像文本。
- 主要产出：
  - 会议归档写入函数
  - 元数据写入逻辑
- 依赖：T2.1、T1.3
- 验收点：
  - 每场会议都有单独目录
  - 可回看该次会议全文

### T2.3 生成会议摘要

- 目标：为每次会议生成结构化摘要。
- 主要产出：
  - 摘要生成提示词
  - `summary.json` 生成逻辑
- 依赖：T2.2
- 验收点：
  - 单次会议可产出：
    - 核心议题
    - 关键结论
    - 新增知识点
    - 不宜长期保留的临时内容

## Phase 3：记忆单元抽取

### T3.1 定义记忆单元 schema

- 目标：统一记忆单元数据结构。
- 主要产出：
  - `memory unit` schema
  - 校验函数
- 依赖：T2.3
- 验收点：
  - 必须包含：
    - `id`
    - `expertSlug`
    - `meetingId`
    - `slot`
    - `value`
    - `scope`
    - `weight`
    - `confidence`
    - `evidence`
    - `status`

### T3.2 定义槽位字典

- 目标：为专家知识体建立规范槽位。
- 主要产出：
  - 槽位枚举
  - 槽位配置表
- 依赖：T3.1
- 验收点：
  - 包含长期、中期、短期三类槽位

### T3.3 从会议摘要抽取记忆单元

- 目标：将会议知识拆成标准化单元，而不是直接改画像文档。
- 主要产出：
  - 抽取提示词
  - 抽取函数
- 依赖：T3.2
- 验收点：
  - 单场会议能生成多条记忆单元
  - 每条记忆单元都能追溯到证据

### T3.4 记忆单元入库

- 目标：将记忆单元写入专家目录。
- 主要产出：
  - `units.jsonl` 写入逻辑
  - 去重 / 幂等逻辑
- 依赖：T3.3
- 验收点：
  - 重复运行不会无脑重复插入相同单元

## Phase 4：加权更新与聚合

### T4.1 实现会议基础权重计算

- 目标：根据会议重要度、长度、证据明确度等计算权重。
- 主要产出：
  - `computeMeetingWeight()`
  - 参数配置表
- 依赖：T3.4
- 验收点：
  - 同一会议内不同类型单元可得到合理权重

### T4.2 实现槽位时间衰减

- 目标：避免历史权重无限累积。
- 主要产出：
  - `decayWeight()`
  - 槽位半衰配置
- 依赖：T4.1
- 验收点：
  - 长期、中期、短期槽位衰减不同

### T4.3 实现候选值竞争模型

- 目标：槽位内允许多个候选值竞争，不直接覆盖。
- 主要产出：
  - `updateSlotCandidates()`
  - 候选值聚合数据结构
- 依赖：T4.2
- 验收点：
  - 同槽位可看到主值和次优候选

### T4.4 实现主值切换规则

- 目标：避免画像因为一场会就抖动。
- 主要产出：
  - `shouldSwitchDominantValue()`
  - 阈值配置
- 依赖：T4.3
- 验收点：
  - 只有达到阈值才切换主值

### T4.5 输出 `aggregates/slots.json`

- 目标：落地每个槽位当前聚合结果。
- 主要产出：
  - `slots.json` 生成逻辑
- 依赖：T4.4
- 验收点：
  - 每个槽位都有：
    - 主值
    - 候选值
    - 置信度
    - 更新时间

## Phase 5：画像展示生成

### T5.1 从槽位聚合生成结构化画像

- 目标：由聚合结果生成 `portrait/summary.json`
- 主要产出：
  - 结构化画像生成器
- 依赖：T4.5
- 验收点：
  - 不再直接依赖会议全文生成最终画像

### T5.2 生成展示用 Markdown 画像

- 目标：生成用户可读的 `portrait/expert.md`
- 主要产出：
  - 文本生成逻辑
- 依赖：T5.1
- 验收点：
  - 画像内容来自聚合结果而非直接拼接旧文档

### T5.3 专家画像 UI

- 目标：在前端展示专家画像与历史来源。
- 主要产出：
  - 专家列表
  - 专家详情页
  - 槽位可视化
- 依赖：T5.2
- 验收点：
  - 可查看当前稳定画像和最近更新来源

## Phase 6：抽离与迁移

### T6.1 定义事件账本 schema

- 目标：所有知识写入都可追踪和撤回。
- 主要产出：
  - `ledger.jsonl` schema
- 依赖：T3.4
- 验收点：
  - 至少支持：
    - `meeting_ingest`
    - `retract`
    - `move`

### T6.2 实现整场会议抽离

- 目标：按来源会议整体撤销污染。
- 主要产出：
  - `retractMeetingImpact()`
- 依赖：T6.1、T4.5
- 验收点：
  - 某次会议可一键从专家画像中移除影响

### T6.3 实现单条记忆单元抽离

- 目标：细粒度纠错。
- 主要产出：
  - `retractMemoryUnit()`
- 依赖：T6.1、T4.5
- 验收点：
  - 单条错误单元可撤回

### T6.4 实现专家迁移

- 目标：挂错专家时可以搬家。
- 主要产出：
  - `moveMeetingToExpert()`
- 依赖：T6.2
- 验收点：
  - 同一场会议可以从 A 专家迁移到 B 专家

### T6.5 抽离与迁移 UI

- 目标：前端可操作抽离和迁移。
- 主要产出：
  - 操作入口
  - 二次确认
  - 结果反馈
- 依赖：T6.4
- 验收点：
  - 用户可以清楚地看到每场会议的处理状态

## Phase 7：问答检索

### T7.1 设计问答上下文组装器

- 目标：按问题动态选择相关知识，而不是全文硬塞。
- 主要产出：
  - `buildExpertQaContext()`
- 依赖：T5.1、T2.3
- 验收点：
  - 输出上下文由三部分组成：
    - 稳定画像
    - 相关会议摘要
    - 原始证据片段

### T7.2 实现问题分类

- 目标：先判断用户问的是长期画像、近期主题，还是某类方法论。
- 主要产出：
  - 问题路由逻辑
- 依赖：T7.1
- 验收点：
  - 不同问题能落到不同上下文组装策略

### T7.3 实现会议摘要组召回

- 目标：选出与当前问题最相关的一组会议。
- 主要产出：
  - 摘要检索逻辑
- 依赖：T7.2
- 验收点：
  - 能召回多次会议组成的相关知识组

## Phase 8：验证与回归

### T8.1 构造测试样本

- 目标：建立几组固定会议样本。
- 主要产出：
  - 正常注资样本
  - 错挂污染样本
  - 迁移样本
  - 新旧冲突样本
- 依赖：全链路基本完成
- 验收点：
  - 可重复执行回归测试

### T8.2 验证加权更新效果

- 目标：验证“当前注资影响合理但不会瞬间颠覆长期画像”。
- 主要产出：
  - 验证记录
- 依赖：T4.5
- 验收点：
  - 长期槽位更新较慢
  - 短期槽位更新较快

### T8.3 验证抽离效果

- 目标：确保污染能被干净回滚。
- 主要产出：
  - 抽离测试结果
- 依赖：T6.4
- 验收点：
  - 抽离后聚合结果恢复正确

### T8.4 验证问答效果

- 目标：确保问答不是全文堆叠，也不会失忆。
- 主要产出：
  - 问答回归样例
- 依赖：T7.3
- 验收点：
  - 对长期问题能调用稳定画像
  - 对专题问题能召回相关会议组

## 建议里程碑

### M1：可归档

- 完成 Phase 1~2
- 结果：会议能规范入库到抽象专家下

### M2：可积累

- 完成 Phase 3~5
- 结果：会议能抽取为记忆单元并稳定生成专家画像

### M3：可纠错

- 完成 Phase 6
- 结果：挂错专家可抽离、可迁移

### M4：可问答

- 完成 Phase 7~8
- 结果：可基于相关知识组做专家问答

## 首批最小闭环

建议先实现以下最小闭环：

1. 专家目录结构
2. 会议全文归档
3. 会议摘要生成
4. 记忆单元抽取
5. 槽位聚合
6. 展示型专家画像
7. 整场会议抽离

这七项完成后，系统就从“难以长期维护的画像拼接”升级成“可积累、可纠错的专家知识体”。
